# Pipeline Documentation

All commands are run from the **project root**.

---

## Overview

Five stages in sequence, producing a trained U-Net model and publication figures:

```
Stage 1 — Features    build_priogrid_features.py, build_feature_store.py
Stage 2 — Target      fetch_wikipedia_ground_truth.py, target_variable_construction.py
Stage 3 — Training    focal_mask_train.py, baseline_*.py
Stage 4 — Evaluation  focal_mask_eval.py, spatial_cv_production.py, feature_ablation.py
Stage 5 — Figures     export_pub_figures.py, export_figure_e.py, reporting.ipynb
```

Stages 1 and 2 can run in parallel after their respective data prerequisites
are in place. Stages 3–5 must run in order.

---

## Production configuration

These constants are hardcoded in `focal_mask_train.py`, `spatial_cv_production.py`,
`feature_ablation.py`, and the two baseline scripts. Any experiment that changes them
must edit each file.

```
TRAIN_CUTOFF     = '2025-09'     # train: Nov 2023–Sep 2025 (23 months)
                                 # val  : Oct 2025–Mar 2026  (6 months)
SEED             = 20269999
NEIGHBOR_RADIUS  = 1             # focal mask dilation (queen neighbors)
FOCAL_OUT_WEIGHT = 0.0           # CE weight for pixels outside focal region
Loss             = 0.7 × CrossEntropy (class-weighted) + 0.3 × DiceLoss
Architecture     = smp.Unet(encoder_name='resnet34', encoder_depth=4,
                            decoder_channels=(128, 64, 32, 16))
NUM_EPOCHS       = 200           # freeze encoder for first 30, then unfreeze at LR=1e-5

INPUT_FEATURES (10, hardcoded in focal_mask_train.py):
  total_events        total_fatalities
  events_gov          events_nug          events_ula         events_kio
  gov_vs_civilians    gov_event_share
  total_events_lag1   total_fatalities_lag1
```

> **Note:** `feature_selection.py` and `selected_features_32.csv` are used only by
> `feature_ablation.py` (appendix ablation). The production training script does
> **not** import `feature_selection.py` — features are hardcoded directly.

## Prerequisites — raw data

The files below must be present before running the pipeline. Processed checkpoints
in `data/processed/` are committed to the repo and allow skipping Stages 1–2 if
you trust the existing ground truth.

| File / pattern | Source | Required? | Notes |
|----------------|--------|-----------|-------|
| `data/raw/ucdp/GEDEvent_v25_1.csv` | [ucdp.uu.se](https://ucdp.uu.se/downloads/) — GED 25.1 annual | **Yes** | ~250 MB |
| `data/raw/ucdp/GEDEvent_v25_01_25_12.csv` | ucdp.uu.se — Candidate Jan–Dec 2025 | **Yes** | **Not committed to repo** — `merge_ucdp_sources.py` fails without it |
| `data/raw/ucdp/GEDEvent_v26_01_26_03.csv` | ucdp.uu.se — Candidate Q1 2026 | **Yes** | Extends panel to Mar 2026 |
| `data/raw/acled/acled_myanmar_YYYY-MM-DD.csv` | [acleddata.com](https://developer.acleddata.com/) | **Yes** | Free registration + API key required. Pipeline auto-selects the file with the most recent date in the filename. |
| `data/raw/gadm/gadm41_MMR.gpkg` | [gadm.org](https://gadm.org/download_country.html) | **Yes** | Layers ADM_ADM_0 and ADM_ADM_1; required by `export_figure_e.py` |

| `data/processed/selected_features_32.csv` | Generated by `notebooks/10_focal_mask_all_features.ipynb` | Optional | Needed only by `feature_ablation.py`. Committed to repo; re-generate by running the notebook if extending the feature ranking. |

## Stage 1 — Feature store

Scripts in `src/data_collection/` and `src/feature_engineering/`. Run in this order:

```bash
# 1. Build actor taxonomy (crosswalk: UCDP actor abbreviation → conflict side)
python src/data_collection/build_actor_taxonomy.py
# Output: data/raw/validation/actor_taxonomy_myanmar.csv

# 2. Merge 3 raw UCDP GED CSV files into one Myanmar dataset
python src/data_collection/merge_ucdp_sources.py
# Input : data/raw/ucdp/GEDEvent_v25_1.csv
#         data/raw/ucdp/GEDEvent_v25_01_25_12.csv   ← must be present
#         data/raw/ucdp/GEDEvent_v26_01_26_03.csv
# Output: data/raw/ucdp/GEDEvent_myanmar_merged.csv

# 3. Filter to post-coup period (Feb 2021+), join actor taxonomy
python src/data_collection/load_ucdp_events.py
# Input : GEDEvent_myanmar_merged.csv, actor_taxonomy_myanmar.csv
# Output: data/processed/myanmar_ucdp_events.csv

# 4. Aggregate UCDP events → PRIOGRID cell × month feature matrix
python src/data_collection/build_priogrid_features.py
# Input : data/processed/myanmar_ucdp_events.csv
# Output: data/processed/myanmar_priogrid_features.csv

# 5. (Optional) Filter PRIOGRID catalog to Myanmar cells
#    Only needed if you want geo features (terrain, resources) in the feature store.
#    priogrid_static.csv and priogrid_yearly.csv must be downloaded first — this
#    script filters them; it does NOT download anything.
python src/data_collection/filter_priogrid_catalog.py
# Input : data/raw/priogrid_static.csv, data/raw/priogrid_yearly.csv,
#         data/processed/myanmar_priogrid_features.csv
# Output: data/processed/priogrid_static_myanmar.csv
#         data/processed/priogrid_yearly_myanmar.csv

# 6. Build full feature store (UCDP base + extended lags + rolling + geo if available)
python src/feature_engineering/build_feature_store.py
# Input : data/processed/myanmar_priogrid_features.csv
#         data/processed/priogrid_static_myanmar.csv  (optional)
#         data/processed/priogrid_yearly_myanmar.csv  (optional)
# Output: data/processed/myanmar_feature_store.csv
```

`myanmar_feature_store.csv` is the X matrix fed to all model scripts.

## Stage 2 — Target variable

Scripts in `src/data_collection/` and `src/feature_engineering/`. Can run in parallel
with Stage 1 after `build_priogrid_features.py` completes (step 4 above).

```bash
# 1. Fetch Wikipedia temporal snapshots via API (~5 min, requires internet)
#    Output is committed to the repo — skip this step unless extending to new months.
python src/data_collection/fetch_wikipedia_ground_truth.py
# Input : Wikipedia API (external)
# Output: data/raw/validation/myanmar_wikipedia_temporal_groundtruth.csv

# 2. Project Wikipedia point labels → PRIOGRID cells (majority vote + LOCF)
python src/data_collection/build_priogrid_labels.py
# Input : data/raw/validation/myanmar_wikipedia_temporal_groundtruth.csv
#         data/processed/myanmar_priogrid_features.csv  (for GID list only)
# Output: data/processed/myanmar_priogrid_labels.csv

# 3. Preprocess ACLED territorial-control events → cell × month aggregates
python src/feature_engineering/acled_preprocess.py
# Input : data/raw/acled/acled_myanmar_*.csv (most recent by filename date)
#         data/processed/myanmar_priogrid_labels.csv
# Output: data/processed/acled_wiki_comparison.parquet

# 4. Apply 6-rule decision cascade (Wikipedia + ACLED) → final target variable
python src/feature_engineering/target_variable_construction.py
# Input : data/processed/acled_wiki_comparison.parquet
#         data/processed/myanmar_priogrid_labels.csv
# Output: data/processed/10_target_variable.parquet   ← primary target file
#         data/processed/myanmar_priogrid_target.csv  (slim CSV copy)
```

`10_target_variable.parquet` is the y file (5,238 cell-months, 185 cells, 6-rule
`reason` column) fed to all model scripts.

**Decision cascade rules:**

| Rule | Condition | Target | `reason` value |
|------|-----------|--------|----------------|
| 0 | No ACLED control event | Wikipedia label | `wiki_only` |
| 1 | ACLED == Wikipedia | Agreed side | `agree` |
| 2 | Wiki = contested + clear ACLED side | ACLED side | `wiki_contested_use_acled` |
| 3 | ACLED ≠ Wiki, Wiki stable | ACLED side | `disagree_stable_wiki_use_acled` |
| 4 | ACLED ≠ Wiki, Wiki in flux | Wikipedia side | `disagree_recent_wiki_use_wiki` |
| 5 | ACLED has both sides active | `uncertain` | `acled_mixed` |

## Stage 3 — Training

```bash
# 1. Train production U-Net (focal mask, 10 features, ~5–10 min on GPU/MPS)
python src/models/focal_mask_train.py
# Input : data/processed/10_target_variable.parquet
#         data/processed/myanmar_feature_store.csv
# Output: models/focal_mask/weights.pt
#         models/focal_mask/predictions.csv   (all months, train + val)
#         models/focal_mask/training_curves.png
#         models/focal_mask_r1.npy            (focal mask array, reused by eval)

# 2. Run baselines (seconds each — no training)
python src/models/baseline_no_change.py
# Output: models/baseline_no_change/predictions.csv

python src/models/baseline_random_proportion.py
# Output: models/baseline_random_proportion/predictions.csv
```

**Re-exporting predictions without retraining:** use
`src/models/focal_mask_export_predictions.py` only when `weights.pt` already exists
and you need to regenerate `predictions.csv` (e.g. after extending the panel).
Config in that script must match `focal_mask_train.py` exactly — verify before use.

## Stage 4 — Evaluation

```bash
# 1. Confusion matrix + transition analysis for the production model
python src/models/focal_mask_eval.py
# Input : models/focal_mask/predictions.csv
# Output: models/focal_mask/eval_confusion_matrix.png
#         models/focal_mask/eval_transitions.png

# 2. Side-by-side comparison of all three models on val set
python src/models/evaluate_baselines.py
# Input : models/focal_mask/predictions.csv
#         models/baseline_no_change/predictions.csv
#         models/baseline_random_proportion/predictions.csv
# Output: models/baseline_comparison.csv

# 3. Spatial cross-validation (10 geographic blocks, 5 folds) — ~20–30 min
python src/models/spatial_cv_production.py
# Input : data/processed/10_target_variable.parquet
#         data/processed/myanmar_feature_store.csv
# Output: models/spatial_cv_results.csv

# 4. Feature set ablation (f10 / f20 / f32 / f93) — ~5 min per variant
python src/models/feature_ablation.py
# Input : data/processed/10_target_variable.parquet
#         data/processed/myanmar_feature_store.csv
#         data/processed/selected_features_32.csv   ← from notebook (see Prerequisites)
# Output: models/feature_ablation_results.csv
```

```bash
#         models/baseline_no_change/predictions.csv

#         src/reporting/figures/C4_roc_curves_transitions.{pdf,png}
#         src/reporting/figures/C5_confusion_matrices_transitions.{pdf,png}

# 2. Transition recall map (Figure E)
python src/visualizations/export_figure_e.py
# Input : models/focal_mask/predictions.csv
#         models/baseline_no_change/predictions.csv
#         models/baseline_random_proportion/predictions.csv
#         data/raw/gadm/gadm41_MMR.gpkg
# Output: src/reporting/figures/E_transition_recall_map.{pdf,png}

# 3. Full reporting notebook (C6 curves, tables, additional diagnostics)
#    Run interactively in Jupyter
jupyter notebook src/visualizations/reporting.ipynb
# Output: src/reporting/figures/C6_macro_roc_pr_transitions.{pdf,png}
#         (and additional figures depending on which cells are run)
```

All export scripts use `src/visualizations/pub_style.py` for consistent figure
style (white background, DejaVu Sans, PDF font type 42, 300 dpi PNG).

## Scripts not part of the production pipeline

The following scripts exist in the repo but are **not** used in the production run.
Do not include them in a clean pipeline execution.

| Script | Why it exists | Why it's not production |
|--------|---------------|------------------------|
| `src/data_collection/build_training_dataset.py` | Earlier pipeline format | Output (`myanmar_training_dataset.csv`) not consumed by any production script; superseded by `10_target_variable.parquet` |
| `src/data_collection/enrich_feature_matrix.py` | Intermediate enrichment step | Superseded by `build_feature_store.py`, which does the same more completely |
| `src/visualizations/map_analysis.ipynb` | Exploratory analysis that led to Figure E | Superseded by `export_figure_e.py` as the canonical export path |
| `notebooks/*.ipynb` (21 notebooks) | Model experiments and EDA | Iterative work — not part of the reproducible pipeline |
| `notebooks/eda_analysis/*.ipynb` (14 notebooks) | Early EDA | Legacy |
